Don't create a separate `.nix` file per app (too small); group app config into shared topic files (`modules/home/default.nix` for cross-platform home-manager, `modules/darwin/default.nix` for darwin-only apps and cask settings), keep raw config files in a data directory beside them (e.g. `modules/home/ghostty/config`; assets shared with system modules, like fonts and images, go in top-level `assets/`), and reserve dedicated `.nix` files for broad topics like `git/`, `shell/` or `linux.nix`.
Keep comments sparse: add one only when it carries information that isn't obvious from the code (the why, a gotcha, a magic value), never to restate what the code does or to label sections.
